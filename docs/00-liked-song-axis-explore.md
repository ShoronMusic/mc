## 1. 一言で何をするか

選曲した **1曲を気に入った**とき、「どこが刺さったのか」の候補（軸）を AI が提示し、その軸から **マインドマップのように枝分かれ**して次の候補曲を展開する。枝には必ず **分岐理由**（同じアーティスト／より激しい／より穏やか／同年代の別アーティスト 等）を付ける。

価値は「おすすめ 3 本」ではなく、**気に入りの言語化**と **自分で辿れる探索**。候補曲は **どの要素でどれだけ近いか**をスコアで明示する（§12）。いまは本体に出さず、**独立ラボの行列 UI** で式と見え方を評価する（§13–14）。

## 2. 既存機能との関係（混同しない）

| 機能 | 発火 | 形 | 役割 |
|------|------|-----|------|
| **次に聴くなら**（試験） | 曲解説後に自動・遅延 | 1〜3 本の直線リスト | 「続けて聴きそうな曲」を短く投げる |
| **本機能** | ユーザー操作（気に入り／明示ボタン） | 中心曲＋軸→枝 | 「なぜ好きそうか」を分解し、軸ごとに候補を辿る |
| **@ チャット** | 自由質問 | 対話 | 曖昧な「あの曲」探しやテーマ旅はこちらに残す |
| **お気に入りハート** | 既存 UI | 保存のみ | 本機能の **強いシグナル**として使う（自動展開はしない） |

**方針（企画時点）**

- 「次に聴くなら」は残す。本機能は **別導線・別 API・別 usage コンテキスト**。
- 同じ曲に対して両方出すとノイズになるため、**部屋チャットの吹き出しに自動でマインドマップは出さない**。
- 候補曲の **YouTube URL はカタログ照合できたときだけ**付ける（「次に聴くなら」と同じハルシネーション防止）。無い場合は検索クエリのみ。

## 3. 体験の骨格

```
                    ┌ 同じアーティスト ─┬ より激しい → 曲A
                    │                 └ より穏やか → 曲B
  [種曲] ─ 気に入りヒント
                    ├ ジャンル（New wave）─┬ 同ジャンル別アーティスト → 曲C
                    │                    └ 隣接ジャンル → 曲D
                    ├ 曲調（疾走感） ─── 同テンポ別曲 → 曲E
                    ├ 時代／トレンド ─── 前後5年・同シーン → 曲F
                    └ 総合的に近い ──── 複数軸の合成スコア上位 → 曲G, H
```

1. **種曲（seed）** が中心。いま選曲した曲、またはお気に入りから選んだ 1 曲。
2. AI（＋カタログ）が **この曲で効いていそうな軸**を数本だけ出す（全部出さない）。
3. ユーザーが軸または極性（より激しい／より穏やか）を開くと、その枝の候補曲が載る。
4. 候補曲を選曲すると、その曲が **新しい中心**になり、探索を続けられる（深さに上限）。

### 3.1 想定シーン

| シーン | 優先 |
|--------|------|
| 一人部屋・パーソナルルームで「この曲が刺さった」 | **主戦場**（[`一人でAI_…`](./一人でAI_新曲開拓とパーソナライズでリピート増.md) の「この曲を気に入ったなら」を具体化） |
| 同期部屋で自分だけ探索 | 可。**選曲者の画面のみ**（他メンバーには配信しない） |
| ゲスト | 不可（ログイン必須。課金・趣向・お気に入りと揃える） |

### 3.2 出す場所（本体と切り離す）

**確定（2026-08-30）**: 部屋の曲解説・おすすめ・チャット吹き出しには **まだ出さない**。先にスコアの見え方を独立機能で評価する。

| 置き場 | 役割 | 本番部屋 |
|--------|------|---------|
| **A. 管理ラボ** `/admin/liked-song-axis-lab` | 種曲を検索 → 候補×軸の行列を評価。STYLE_ADMIN。第一候補 | 非接続 |
| **B. ラボ用モーダル** | 同じ行列 UI をモーダルに載せる。管理ラボ内、または STYLE_ADMIN 限定の部屋ボタン（解説フロー非接続） | 任意・後から |
| **C. CLI** `scripts/liked-song-axis-lab.ts` | 種曲 ID を渡して JSON / TSV を出す。スコア式の回帰テスト向き | 非接続 |

部屋本体への組み込みは、ラボで「この行列が読める・スコアが納得できる」となってから。マインドマップ見た目はさらに後（§8 Phase 5）。

## 4. 軸（要素）カタログ

ユーザー案（アーティスト／ジャンル／パフォーマンス／曲調／時代のトレンド）を正とし、実装しやすい順に **データが既にある軸**を先に使う。

### 4.1 第1群 — カタログで機械的に辿れる（優先）

| 軸 ID | 表示例 | データ源 | 枝の例（分岐理由） |
|-------|--------|----------|-------------------|
| `artist` | 同じアーティスト | `artists` / Music8 `artist_index.json` / `song_credits` | 同じ人の別曲／別時代のその人 |
| `genre` | ジャンル | `song_genres` + `catalog_genres`、Music8 `classification` | 同じジャンル／隣接ジャンル |
| `style` | スタイル | `song_styles` + `catalog_styles`、アプリ `SONG_STYLE_OPTIONS` | 同じスタイルの別曲 |
| `era` | 時代 | `songs` 原盤日、Music8 `releases`、YouTube 公開日は補助 | 前後5年／もっと前／もっと後 |
| `vocal` | ボーカル | `song_vocals` + `catalog_vocals` | 同じ声質カテゴリ |

**同じアーティストが最も容易**で、MVP の本命。その中でもジャンル・年代・曲調が取れる曲だけを残し、**同一アーティスト内の「総合的に近い」**を先に出す。

### 4.2 第2群 — 半構造＋短い AI 補完

| 軸 ID | 表示例 | データ源 | 注意 |
|-------|--------|----------|------|
| `mood` | 曲調・空気感 | 曲解説・`facts_for_ai`・モデルの短タグ | 主観が強い。極性（激しい／穏やか）向き |
| `performance` | パフォーマンス | `song_videos.variant`（official / live / lyric 等）、Music8 `recording.kind` | 「ライブの熱量」と「スタジオの完成度」を混同しない |
| `trend` | 時代のトレンド・シーン | 解説・facts の文脈（new wave、ブリットポップ等） | 根拠なしチャート／バズは既存 [`ai-output-policy.ts`](../src/lib/ai-output-policy.ts) どおり禁止 |
| `related_artist` | 関連アーティスト | `artists.related_artists_raw`（未正規化）、クレジット共通 | 幻覚アーティストを出さない。カタログに居る人優先 |
| `credits` | 作り手 | `song_credits`（作家・プロデューサー） | データがある曲だけ |

### 4.3 第3群 — 将来（今は軸に出さない）

歌詞テーマの深掘り、BPM 実測、Spotify audio features、ユーザーが自分で書いた「サビが好き」自由文。趣向メモ（`user_ai_taste_summary`）は **候補の並べ替え**に使い、軸そのものにはしない。

### 4.4 極性（同じ軸の中の分岐）

枝分かれするときは、軸名だけでなく **方向**をラベルにする。

| 軸 | 極性の例（日本語ラベル） |
|-----|---------------------------|
| `mood` | より激しい／より穏やか／同じ温度感 |
| `era` | 少し前／同じ頃／少し後 |
| `artist` | 同じ人の初期／全盛／近年 |
| `genre` | 同じジャンルの王道／隣接ジャンルへ一歩 |
| `performance` | スタジオ版に近い／ライブ寄りの熱量 |
| `composite` | 総合的に近い（複数軸の合成。極性なし） |

**ルール**: 枝には必ず `axis` + `polarity`（または `same`）+ 短い `reasonLabel`（例: 「同じ New wave で、もう少し疾走感」）。ラベルが説明になっていない枝は出さない。

## 5. 候補の出し方（総合的に近い、を含む）

### 5.1 原則: 曲の実体はカタログ、AI は軸と理由

Gemini に「似た曲を自由に挙げさせる」と URL・存在しない曲が混ざる。既存の「次に聴くなら」と同じく:

1. **候補集合**は mc DB / Music8 から取る（同一アーティスト、同ジャンル、同スタイル、年代ウィンドウ）。
2. **スコア**はルール＋軽い重み（下記）。
3. Gemini は (a) 種曲の **効いていそうな軸の順位**、(b) 極性ラベル、(c) 候補が決まったあとの **一言理由**。
4. カタログに無い曲は、MVP では出さない。足りなければ「この軸ではライブラリに近い曲が少ない」と明示。

後から「次に聴くなら」型の検索クエリ付き・カタログ外候補を **1 本だけ**足す拡張はあり得るが、マップの本体にはしない。

### 5.2 同一アーティスト内（MVP）

1. `artist_index` または `song_credits` でそのアーティストの曲一覧（種曲自身と既出は除外）。
2. 取れる属性で距離を足し合わせる。

| 信号 | 近い | 遠い |
|------|------|------|
| ジャンル集合の重なり | 高い | 低い |
| スタイル一致 | 高い | 低い |
| 原盤年の差 | 5年以内を優先 | それ以上は減点（「次に聴くなら」の era 方針と揃える） |
| 録音種別 | 同じ `recording.kind` | live vs original など |
| ヒット規模 | 任意。ニッチ種曲なら緩和（「次に聴くなら」の `popularityFit` と同じ思想） |

**総合スコア**はこれらの加重和。ユーザーが「総合的に近い」を選んだときはこの順。個別軸を開いたときは、その軸の一致を大きく、他はタイブレーク程度。

ラボでは **軸ごとの生スコアを必ず返す**（並べ替え用の合成値だけにしない）。表示契約は §12。

### 5.3 アーティストをまたぐ

同一アーティストで候補が足りない、またはユーザーがジャンル／時代軸を開いたとき。

- フィルタ: 同じ `catalog_genres` / `catalog_styles`、年代 ±5 年。
- 並べ替え: ジャンル重なり → スタイル → 年差 → 関連アーティスト・共通クレジット。
- 上限: 1 枝あたり **2〜4 本**。マップ全体の同時表示は抑える。

### 5.4 種曲の軸そのものの出し方

「この曲が好きなら、ここが刺さっている可能性がある」は、次を短く渡して Gemini に **軸の順位と極性の候補だけ**出させる。

- Music8 `facts_for_ai` / `classification`（あれば）
- 直近の曲解説スニペット（comment-pack と同等、長さ上限あり）
- ユーザー趣向（`fetchUserTasteContextForChat`、任意）

モデルは曲名を発明しない。出力は軸 ID の列挙と日本語ラベル。候補曲 ID はサーバーが後から付ける。

## 6. 操作・状態

### 6.1 開始

第一候補（未確定・議論用）:

1. 再生中（または直前に選んだ曲）に **「この曲の好きを探る」**（仮称）。
2. お気に入りハート直後に、同じ導線を小さく出す（毎回強制しない。1 セッション 1 回案内など）。
3. マイページのお気に入り／マイリストから種曲を選んで開始（Phase 後半）。

自動開始はしない（原価・部屋のノイズ）。

### 6.2 深さ・ループ

| 項目 | 企画案 |
|------|--------|
| 深さ | 種曲から **3 hop** まで（A→軸→曲B→軸→曲C）。それ以上は「この曲を新しい種にする」でリセット |
| 同一セッション | 既に出した曲は再掲しない |
| 選曲 | 候補に `watchUrl` があれば既存の選曲フローへ。解説・クイズは通常どおり。本機能のマップは開いたまま残せるかは UI 次第 |
| 部屋の AI 設定 | `user_room_ai_features` に項目を足すか、おすすめ曲と同じ「自分 ON」にするかは **未決** |

### 6.3 課金・フラグ

- **ma のみ**。ゲスト・mc は出さない。
- マスターフラグ（例: `LIKED_SONG_AXIS_EXPLORE_ENABLED`）＋任意 β UID。既存のおすすめ試験と同じ型。
- Gemini usage コンテキスト案: `liked_song_axis_explore`（軸分析）／枝展開は同コンテキストまたは `_expand`。
- クレジット: **未決**。案 A = 選曲 1 クレジットに含めて探索は付帯、案 B = 探索開始で 0.5、案 C = お試し対象外の試験無料。実装前に [`00-prepaid-pricing-summary.md`](./00-prepaid-pricing-summary.md) と揃える。
- 開発者／サポーター無制限は既存 UID リストに乗せる。

| リスク | 避け方 |

## 12. 類似スコアの契約（候補が「どの要素でどれだけ近いか」）

評価と UI の前提。**合成点だけ見せない。** 各候補について、軸ごとの類似を明示する。

### 12.1 1 セルの中身

| フィールド | 意味 |
|------------|------|
| `axis` | `artist` / `genre` / `style` / `era` / `vocal` / `mood` / `performance` / `trend` / `credits` 等 |
| `score` | 0–100 の整数（近いほど大きい）。**欠損は null**（0 は「似ていない」、null は「測れない」） |
| `raw` | 人が検証できる生値（年差、ジャンル Jaccard、同一アーティスト 0/1 等） |
| `label` | 短い日本語（「同じ New wave」「年差 3」「別アーティスト」） |
| `evidence` | 任意。重なったジャンル名、リリース年ペアなど |

種曲自身の行は出さない（対角は常に 100 で無意味）。比較不能な軸はセルをグレーの「—」。

### 12.2 軸ごとの測り方（L0・カタログ優先）

| 軸 | 100 に近い | 0 に近い | 欠損 |
|----|----------|----------|------|
| `artist` | 同一メインアーティスト | 別人 | クレジット無し |
| `genre` | ジャンル集合の重なり（Jaccard 等） | 共通なし | どちらかにジャンル無し |
| `style` | 同一スタイル | 不一致 | どちらか不明 |
| `era` | 原盤年差 0 | 差が大きい（キャップ例: 20 年で 0） | 年が無い |
| `vocal` | 同一ボーカル分類 | 不一致 | 無し |
| `performance` | 同じ `recording.kind` / `variant` | live vs studio 等 | 無し |
| `mood` / `trend` | L1 以降。タグ一致やモデル自己評価 | — | L0 では列ごと省略可 |
| `composite` | 上の加重平均（欠損軸は分母から除外） | — | 有効軸が 0 本なら null |

**欠損を 0 にしない。** 0 詰めすると「似ていない」と「データが無い」が区別できず、評価不能になる。

### 12.3 1 候補のペイロード（イメージ）

```json
{
  "songId": "…",
  "artist": "Duran Duran",
  "title": "Rio",
  "watchUrl": "https://www.youtube.com/watch?v=…",
  "composite": 72,
  "axes": {
    "artist": { "score": 100, "raw": { "same": true }, "label": "同じアーティスト" },
    "genre": { "score": 67, "raw": { "jaccard": 0.67, "overlap": ["New wave"] }, "label": "New wave が共通" },
    "era": { "score": 80, "raw": { "yearDelta": 2 }, "label": "年差 2" },
    "style": { "score": 100, "raw": { "same": true }, "label": "Pop" },
    "mood": null
  }
}
```

並べ替えキーは `composite`。**表示の主役は軸列**。総合は右端（または左端）の 1 列に留める。

## 13. 評価用 UI（マトリックスを主、他は切替）

目的は「この候補はジャンルは近いが年代が遠い」が一目で分かること。探索マップより **表** が先。

### 13.1 マトリックス（第一候補）

行 = 候補曲、列 = 軸。セル = スコア（色）＋短いラベル。

```
種曲: Duran Duran — Hungry Like the Wolf (1982)   候補: 同一アーティスト 12 曲

              総合  アーティスト  ジャンル   スタイル  時代   曲調   演奏
Rio           72    100         67        100      80     —     100
The Reflex    64    100         50        100      70     —     100
Ordinary World 41   100         20        100      20     —     100
```

- セル背景は 0–100 のヒート（低い=寒色、高い=暖色）。null は無色＋「—」。
- ヘッダーをクリックでその軸の降順ソート。
- セルクリックで `raw` / `evidence` を下またはサイドに出す（年ペア、共通ジャンル）。
- 行クリックでその曲を種曲にして再計算（ラボ内だけ。部屋選曲はしない）。

スマホでは列が多いので、**列の表示/非表示**と横スクロール。ラボはデスクトップ前提でよい。

### 13.2 併記して試すビュー

評価中にタブで切り替え、どれが「納得できるか」を見る。本体に全部載せない。

| ビュー | 向くこと | 向かないこと |
|--------|----------|--------------|
| **ヒート行列**（13.1） | 要素ごとの比較、外れ値発見 | 曲数が 30 を超えると疲れる |
| **バー比較** | 選んだ 2〜3 曲を軸ごとに横棒 | 候補が多いとき |
| **レーダー** | 1 曲 vs 種曲の形 | 多曲比較。ラボのオマケ程度 |
| **ランキング＋チップ** | 総合順に、高い軸だけチップ | 低い軸が見えにくい |

L1 の合格条件: ヒート行列だけで「このスコア式はおかしい」と指摘できること。レーダーは必須にしない。

### 13.3 種曲ヘッダ（行列の上）

種曲の **事実だけ**（AI の推測と混ぜない）。

- アーティスト / 曲名 / 年 / スタイル / ジャンル / 録音種別
- 欠損している軸を明示（「曲調は未推定 → 列は —」）
- 候補集合の説明（「同一アーティスト 12 / 表示 12」「同ジャンル他アーティストは未実行」）

### 13.4 評価メモ（人の判定）

ラボ画面に、候補ごとまたはセルごとに短い印を付けられるとスコア式の改善が速い。

| 印 | 意味 |
|----|------|
| 近い | 体感どおり近い |
| 遠い | スコアは高いが体感は遠い（式のバグ候補） |
| データ不足 | 欠損なのに総合が高い、など |

永続化は後回しでよい。最初は画面メモ＋ JSON ダウンロードで足りる。

## 14. 独立ラボの置き方

### 14.1 管理ページ（推奨・最初に作る）

既存の **曲引き**（`/admin/song-lookup`）と同じ型。

| 項目 | 内容 |
|------|------|
| パス | `/admin/liked-song-axis-lab` |
| 権限 | `STYLE_ADMIN_USER_IDS`。mc デプロイでは `/admin` ごと 404 |
| 入力 | YouTube ID / URL、または曲名検索（song-lookup と同様） |
| 出力 | §13 の行列。JSON ダウンロード。**Gemini で候補選出**（`liked_song_axis_explore`） |
| ナビ | `admin-sections.ts` の AI 運用（「気に入り軸ラボ（試験）」） |

部屋の `RoomWithSync` / 解説成功フックには **配線しない**。

### 14.2 モーダル

行列コンポーネントをモーダルに載せ、2 箇所から同じ UI を開ける。

1. 管理ラボ内の「大きく見る」（ページ埋め込みと同じ中身）。
2. （任意・後）部屋の STYLE_ADMIN 専用ボタン。**曲解説・次に聴くならとは独立。** 押した人の画面にだけ出す。

特集ページモーダルと同列のオーバーレイを想定。チャット吹き出しには埋め込まない。

### 14.3 CLI（スコア式の回帰）

UI を待たず式を試す用。

```text
npx tsx scripts/liked-song-axis-lab.ts --seed <youtubeId|songId> --set artist --limit 20
```

標準出力は TSV または JSON（§12.3 の配列）。単体テストは固定種曲＋固定カタログ断片で `score` と `null` を固定する。

### 14.4 やらないこと（ラボ期間）

- 曲解説後の自動表示
- 他メンバーへの配信
- クレジット消費 UI
- マインドマップ描画
- カタログ外の幻覚候補

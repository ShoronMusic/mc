## 6. 損益 — ¥1,000＝40曲は赤字か？

### 結論

| 観点 | 赤字リスク |
|------|-----------|
| **1パック（40曲フル利用）** | **極めて低い** |
| **月次事業全体** | 有料購入が少ないと **固定費で赤字** |

### 1パック損益（全クレジット消費）

手取り: **¥1,000 × 0.964 ＝ ¥964**

| 原価想定 | 40曲 変動費 | 限界利益 |
|----------|------------|----------|
| 全部 DB | ¥16 | **約 ¥948** |
| 混在 r=0.3 | ¥30 | **約 ¥934** |
| 全部 NEW | ¥64 | **約 ¥900** |
| 多いとき目安（¥3/曲） | ¥120 | **約 ¥844** |

**パック単位で赤字になる条件**: 1曲あたり原価が **約 ¥24.1**（＝964÷40）を超え続ける場合。現状試算（¥0.4〜1.6）からは **15倍以上**の乖離が必要。

¥500＝20曲も同じ実効単価（¥25/曲）。手取り ¥482・限界利益（r=0.3）約 **¥467**。

### 月次固定費の損益分岐（r=0.3・フル消費想定）

| 固定費 | ¥1,000パック | ¥500パック |
|--------|-------------|-----------|
| **B ¥7,500** | **9パック/月** | **17パック/月** |
| **C ¥12,100** | **13パック/月** | **26パック/月** |

※ 無料ユーザー・部屋共通 AI（tidbit・エージェント）・お試し10曲のコストは **別枠**。

### 別枠コスト（パック黒字でも全体が赤字になりうる）

| 項目 | 内容 |
|------|------|
| 選曲のみ無料ユーザー | Ably・ホスティング（AI 変動費ほぼゼロ） |
| 部屋共通 AI | 主催者原価（`room_owner` / `ai_agent`） |
| お試し20曲 | 1人あたり約 ¥15〜32（集客コスト） |
| クレジット未使用 | 前払いのみ → 変動費はさらに低い（キャッシュ有利） |

チャット横 Canvas: `canvases/prepaid-yen1000-40songs-break-even.canvas.tsx`（損益表・分岐グラフ）

## 7. 決済実装（Phase D 予定）

### Stripe

- **方式**: Checkout Session（一回購入）→ Webhook でクレジット加算
- **都度課金**: しない（手数料負け）
- **プラットフォーム**: まず **モバイル Web + Stripe**。ネイティブアプリ化時に IAP 検討

### DB（案）

| テーブル | 用途 |
|----------|------|
| `user_ai_credits` | `user_id` · `credits_remaining` · 更新時刻 |
| `user_ai_credit_transactions` | 購入（Stripe）· 消費（選曲/@）· 監査 |

**保全**: 本番は **Supabase Pro**（日次バックアップ・保持7日）契約済み。詳細は `docs/supabase-user-ai-credits-table.md`「バックアップ・保全」。

### 判定フロー（既存拡張）

```
trial 残あり → B1（お試し消費）
trial 枯渇 & credits > 0 → B3（full・クレジット消費）
それ以外 → B2（none・選曲のみ or チャージ案内）
```

既存: `ai-selection-mode.ts` · comment-pack / chat のサーバーガード · `aiMode` 二重ガード。
